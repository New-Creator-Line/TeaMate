# 03. Фаза 2: Сценарии Диалога ИИ-Ассистента и Интерактивные Потоки

## 1. Архитектурный Принцип: Детерминированный C# Перехват

Чтобы исключить поломки JSON-разметки или галлюцинации LLM:
1. Нейросеть (Nemotron-3.5 120B / Gemini) занимается **только пониманием смысла и вызовом инструментов**.
2. В кодовой базе `Fotoprint.Core/Agents/FotoprintAiAgent.cs` вызов инструмента `find_free_slots` **перехватывается на уровне C#**:
   - Агент получает строго валидированный JSON свободных слотов от `Fotoprint.Mcp.Calendar`.
   - C#-код автоматически конструирует строго типизированный объект `ActionCard` со слотами и кнопками выбора длительности.
   - Нейросети возвращается результат выполнения тула, и она формирует вежливый текстовый ответ на русском языке.
   - Итоговый HTTP-ответ шлюза объединяет:
     ```json
     {
       "reply": "Текст от нейросети...",
       "action_card": { /* Сформировано C#-кодом без галлюцинаций */ }
     }
     ```

## 2. Бесстейтовый (Stateless) Сценарий Human-in-the-Loop

```
Пользователь: «Назначь встречу с Кузнецовым сегодня после 14:00 на 30 минут»
```

### Шаг 1: Определение участника и слотов
- LLM вызывает `find_free_slots(organizer_id: 1, participant_ids: [2], date: "2026-11-12", duration_minutes: 30)`.
- Бэкенд отсекает прошедшие слоты (до 14:00) и возвращает доступные: `14:30 - 15:00`, `16:00 - 16:30`.
- C#-шлюз прикрепляет `action_card` с кнопками слотов.

### Шаг 2: Выбор слота пользователем
- Пользователь кликает по кнопке: `[ 📅 14:30 – 15:00 ]`.
- Фронтенд **локально** (без запросов в БД) формирует карточку подтверждения:
  ```markdown
  📋 **Предварительный просмотр встречи:**
  • **Тема:** Встреча с Кузнецовым И.П.
  • **Дата и время:** 12 ноября 2026, 14:30 – 15:00 (МСК)
  • **Организатор:** Смирнов Алексей Сергеевич
  • **Участник:** Кузнецов Иван Петрович
  ```
  Параметры сохраняются в объекте кнопки:
  ```javascript
  const payload = {
    title: "Встреча с Кузнецовым И.П.",
    startTime: "2026-11-12T14:30:00+03:00",
    endTime: "2026-11-12T15:00:00+03:00",
    organizerId: 1,
    participantIds: [2]
  };
  ```

### Шаг 3: Подтверждение (Commit)
- Пользователь нажимает: `[ ✅ Подтвердить и создать ]`.
- Фронтенд делает прямой вызов: `POST /api/calendar/confirm` с `payload`.
- Сервер атомарно создает встречу со статусом `'scheduled'`.
- В ответ приходит статус успеха и данные эмуляции уведомления.

### Шаг 4: Отображение статуса и заглушки оповещения
В чате выводится системное подтверждение:
> **✅ Встреча успешно запланирована в корпоративном календаре!**  
> `[🔔 Оповещение участникам: эмулировано (заглушка спринта: Telegram / Bitrix24)]`

И виджет календаря в шапке моментально обновляется: на текущей дате появляется зеленый кружок.

## 3. Сценарий: Запрос без длительности (Длительность в один клик)

```
Пользователь: «Организуй встречу с Еленой Морозовой завтра»
```
1. Так как длительность не указана явно текстом, C#-шлюз генерирует `action_card` типа `duration_selection`:
   - Кнопки: `[ ⏱ 15 мин ]  [ ⏱ 30 мин (стандарт) ]  [ ⏱ 45 мин ]  [ ⏱ 1 час ]`
2. Ассистент спрашивает:
   > «На какую ориентировочную длительность запланировать встречу с Еленой Морозовой?»
3. Клик по кнопке отправляет быстрый триггер (например, «Встреча на 30 минут»), запуская генерацию свободных слотов.

## 4. Сценарий: Прошедший день или отсутствие окон

```
Пользователь: «Запланируй встречу с Кузнецовым сегодня в 10:00» (а сейчас уже 14:00)
```
1. Алгоритм `FindFreeSlotsAsync` видит, что 10:00 уже в прошлом.
2. Он отсекает утро и проверяет оставшиеся часы дня.
3. Если после 14:00 есть окна — предлагает их:
   > «Время 10:00 уже прошло. Сегодня у Ивана Кузнецова свободно: 14:30–15:00 и 16:00–16:30.»
4. Если до конца дня окон нет — ассистент автоматически проверяет следующий рабочий день и выдает слоты на завтра.
