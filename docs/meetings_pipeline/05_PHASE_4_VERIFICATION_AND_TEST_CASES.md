## 1. Цель фазы
Обеспечить 100% повторяемость, верифицируемость и готовность к демонстрации функционала протоколирования и RAG перед жюри хакатона.

## 2. Чеклист верификации (QA Checklist)

- [ ] **1. Проверка окружения**:
  * Движок C++ `tsukiko-recognizer` (или системный whisper.cpp) доступен и отвечает на `--version`.
  * Модель `ggml-large-v3-turbo.bin` (или base/small) скачана в папку `tools/models/` или `~/.local/share/tsukiko/models/`.
  * База данных PostgreSQL запущена с установленным расширением `vector`.
- [ ] **2. Тест автодетекта входа**:
  * Загрузка аудиофайла `.m4a` запускает ветку Whisper.
  * Загрузка `.txt` файла с Google Meet форматом парсится без запуска транскрибатора.
- [ ] **3. Тест диаризации и анализа MoM**:
  * Спикеры сопоставлены с реальными именами участников.
  * Если дедлайн не назван — в поле стоит строго `«требует уточнения»`.
- [ ] **4. Тест генерации артефактов**:
  * В ответ на запрос генерируется валидный файл протокола `.docx`.
- [ ] **5. Тест Meeting RAG**:
  * На вопрос о конкретной фразе спикера ассистент выдает точный таймкод и имя сотрудника.

## 3. Тестовые сценарии (cURL)

### Тест-кейс 1: Загрузка готового транскрипта Google Meet
Создадим файл `test_meet_transcript.txt`:
```text
00:00:10 - Иван Иванов: Коллеги, начинаем синк по тиражу корпоративных фотокниг.
00:00:15 - Максим: Да, привет. Иван, когда закончим приладку на Heidelberg?
00:00:22 - Иван Иванов: Приладка идет, к 18:00 отдаем весь тираж на резку и ламинацию.
00:00:30 - Максим: Отлично. Анна, возьми на контроль отгрузку в СДЭК до 19:00.
00:00:35 - Анна: Договорились, курьер уже забронирован на 19:15.
```

Запрос к API:
```bash
curl -X POST "http://localhost:5000/api/meetings/process" \
  -F "file=@test_meet_transcript.txt" \
  -F "title=Срочный синк по тиражу фотокниг" \
  -F "source=google_meet"
```

Ожидаемый ответ:
```json
{
  "success": true,
  "meeting_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "title": "Срочный синк по тиражу фотокниг",
  "summary": "На совещании обсудили статус выполнения тиража корпоративных фотокниг на машине Heidelberg...",
  "decisions": [
    "Тираж отдается на резку и ламинацию к 18:00."
  ],
  "action_items": [
    {
      "task": "Отгрузка тиража в СДЭК до 19:00",
      "assignee": "Анна",
      "deadline": "до 19:00",
      "context": "Курьер забронирован на 19:15"
    }
  ],
  "speaker_turns_count": 5,
  "docx_url": "/api/meetings/3fa85f64-5717-4562-b3fc-2c963f66afa6/protocol.docx"
}
```

### Тест-кейс 3: RAG-поиск по стенограммам встреч
```bash
curl -X POST "http://localhost:5000/api/meetings/query" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "Когда Иван пообещал закончить приладку на Heidelberg?",
    "meeting_id": null
  }'
```

Ожидаемый ответ:
```json
{
  "answer": "Иван Иванов пообещал закончить приладку на Heidelberg к 18:00 (реплика на 00:00:22).",
  "citations": [
    {
      "meeting_title": "Срочный синк по тиражу фотокниг",
      "speaker": "Иван Иванов",
      "timestamp": "00:00:22",
      "quote": "Приладка идет, к 18:00 отдаем весь тираж на резку и ламинацию."
    }
  ]
}
```

## 4. Сценарий презентации для жюри (Demo Script)

1. **«Боль бизнеса»**: Руководители и начальники цехов «ООО Фотопринт» тратят часы на созвоны в Google Meet. Договоренности забываются, дедлайны размываются, а ручной ввод протоколов в Битрикс24 отнимает ценное время.
2. **«Наше решение за 1 секунду»**: 
   * Показываем загрузку файла созвона.
   * Система автоматически определяет спикеров, вычленяет четкие поручения и генерирует официальный `.docx` протокол.
3. **«Интеллектуальный поиск»**:
   * В прямом эфире пишем ассистенту вопрос: *«Кто обещал проконтролировать отгрузку в СДЭК?»*
   * Ассистент мгновенно отвечает: *«Анна (таймкод 00:00:35), курьер забронирован на 19:15»* со ссылкой на точную секунду встречи.
