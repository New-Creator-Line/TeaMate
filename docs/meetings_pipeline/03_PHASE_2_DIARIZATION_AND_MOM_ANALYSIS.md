# 03. Фаза 2: Диаризация и анализ протокола (Diarization & MoM Analysis)

## 1. Цель фазы
1. **Атрибуция спикеров (Speaker Diarization)**: Если в транскрипте нет имен спикеров (сырое аудио из Whisper), языковая модель сопоставляет реплики с реальными участниками встречи.
2. **Интеллектуальный анализ встречи (Minutes of Meeting, MoM)**: Формирование краткой выжимки, списка решений, конкретных задач с дедлайнами и рисков.
3. **Единый проход LLM**: Объединение диаризации и анализа MoM в один вызов Gemini для минимизации задержки и расхода токенов.

---

## 2. Архитектура DiarizationLM на базе Gemini

Вместо установки тяжелых акустических моделей кластеризации (pyannote весом 2–4 ГБ), система использует семантический контекст диалога:

```
[Вход: Список участников встречи из календаря/формы]
Участники: ["Максим (Директор)", "Иван (Начальник цеха)"]

[Вход: Сегменты от Whisper с секундами]
[00:01:10 - 00:01:14] Максим, когда закончим приладку на Heidelberg?
[00:01:15 - 00:01:20] К 18:00 тираж отдадим на резку.

            │
            ▼
┌────────────────────────────────────────────────────────┐
│               Gemini Diarization Prompt                │
│ 1. Анализ обращений: "Максим, когда..." -> говорит Иван│
│ 2. Анализ ответов: "К 18:00 отдадим..." -> говорит Максим│
│ 3. Сохранение исходного текста реплики без искажений  │
└────────────────────────────────────────────────────────┘
            │
            ▼
[Выход: Размеченные реплики Speaker Turns]
- Иван [00:01:10 - 00:01:14]: "Максим, когда закончим приладку на Heidelberg?"
- Максим [00:01:15 - 00:01:20]: "К 18:00 тираж отдадим на резку."
```

## 3. Системный промпт для Gemini (Единый вызов)

```text
Ты — ведущий аналитик корпоративных совещаний компании «ООО Фотопринт».
Твоя задача:
1. Выполнить точную атрибуцию реплик участников встречи (Speaker Turns).
2. Сформировать структурированный протокол совещания (Minutes of Meeting).

СПИСОК УЧАСТНИКОВ ВСТРЕЧИ:
{participants_list}

ПРАВИЛА АТРИБУЦИИ СПИКЕРОВ (DIARIZATION):
1. Опирайся на прямые обращения по именам («Максим, посмотри...» означает, что отвечает Максим, а обращается другой участник).
2. Опирайся на контекст ролей (начальник цеха говорит о станках, ламинации и приладке; менеджер — о клиентах и СДЭК).
3. Если говорящего невозможно определить со 100% уверенностью — укажи «Спикер 1», «Спикер 2» или «Неизвестный спикер».
4. СОХРАНЯЙ ИСХОДНЫЙ ТЕКСТ РЕПЛИК БЕЗ ИСКАЖЕНИЙ. Не перефразируй слова.

ПРАВИЛА ИЗВЛЕЧЕНИЯ ПРОТОКОЛА (MoM):
1. Принцип «Без додумывания»: фиксируй только то, что явно прозвучало.
2. Если дедлайн не назван — пиши «требует уточнения».
3. Если исполнитель задачи не назначен — пиши «требует уточнения».

ВЕРНИ ОТВЕТ СТРОГО В ФОРМАТЕ JSON:
{
  "title": "Тема совещания",
  "summary": "Краткое связное резюме встречи на 3-5 предложений",
  "decisions": [
    "Принятое решение 1",
    "Принятое решение 2"
  ],
  "action_items": [
    {
      "task": "Суть поручения",
      "assignee": "ФИО ответственного",
      "deadline": "Срок или 'требует уточнения'",
      "context": "Контекст обсуждения"
    }
  ],
  "risks": [
    {
      "risk": "Описание риска / блокера",
      "impact": "К чему приведет"
    }
  ],
  "speaker_turns": [
    {
      "speaker": "Имя участника",
      "start_seconds": 70.0,
      "end_seconds": 74.0,
      "text": "Точный текст реплики"
    }
  ]
}
```

## 4. Защита персональных данных (PII Masking)

В соответствии с регламентами безопасности компании «ООО Фотопринт» (разобранными на лекции по CRM «Мэри»), перед отправкой транскрипта во внешнюю LLM локально применяется токенизатор персональных данных:

1. Номера телефонов клиентов $\to$ `[CLIENT_PHONE_1]`
2. Личные email-адреса $\to$ `[CLIENT_EMAIL_1]`
3. Паспортные данные / номера карт $\to$ `[PAYMENT_ID_1]`
4. После получения JSON ответа от Gemini маркеры демаскируются обратно в локальном контуре сервера перед сохранением в PostgreSQL.

## 5. DTO-модель результата анализа

```csharp
namespace Fotoprint.Core.Models.Meetings;

public record ActionItem(
    string Task,
    string Assignee,
    string Deadline,
    string? Context
);

MeetingRisk(
    string Risk,
    string? Impact
);

public record SpeakerTurn(
    string Speaker,
    double StartSeconds,
    double EndSeconds,
    string Text
);

public record MeetingAnalysisResult(
    string Title,
    string Summary,
    List<string> Decisions,
    List<ActionItem> ActionItems,
    List<MeetingRisk> Risks,
    List<SpeakerTurn> SpeakerTurns,
    List<string> Participants
);
```
